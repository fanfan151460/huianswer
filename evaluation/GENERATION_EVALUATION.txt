生成评测：采集完整问答，再用 Ragas 与必要要点覆盖率评分（generation-v2）
====================================

一、这轮测什么
- 沿用现有20道开发题；16道有答案的知识问答计算指标。
- 另外4道澄清、无答案、闲聊题标为 manual_review，对照预期行为人工检查。
- 使用现有完整问答接口 POST /hui-ansWer/chat/stream。
- 不指定正确知识库，不向问答模型发送参考答案。
- 实际资料来自本次 SSE evaluation 事件，回答由 delta 拼接。
- 不连接数据库、不回查片段、不复用上一轮独立检索的返回值。
- 采集器保留 evaluation 中全部片段，不另外截取前六个。
- 这轮不比较三种检索策略，使用项目当前默认的完整问答链路。

二、准备
1. application.yml 中 rag.evaluation.enabled: true，然后重启 Java 服务。
   evaluation 事件必须包含本次送给回答模型的片段正文；空资料时也发送 []。
2. 和之前一样登录，取得 token。
   默认用户名 admin；不同用户名用 --username 指定。
3. 登录 token 可放在 HUIANSWER_EVAL_TOKEN；不设置则运行时隐藏输入。
   脚本不会保存 token，不会自动登录，也不会重试失败的问答。

三、先采集一道题
普通 Python 3.10+ 即可，不用安装新依赖：

python D:\code01\HuiAnswer\evaluation\collect_generation.py --limit 1

结果在：
evaluation/xinglan-shop-v1/runs/generation/<本次时间>/results.jsonl
同目录 run.json 保存运行状态和题号，不含登录凭据。

检查这一行：
- status 应为 success。
- evaluation_received、done_received 应为 true。
- response 是拼接后的完整回答。
- chunks、retrieved_contexts 是这次回答真正使用的片段。
- reference 是采集当时的参考答案快照，只供后续评分。
- 评分默认按题号加载 cases/generation_reference_v2.json 的修订标准，不改原始采集文件。
- cases/generation_reference_v2.md 是新版参考答案和42个知识问答必要要点的易读版。

只检查题集、不请求服务：
python D:\code01\HuiAnswer\evaluation\collect_generation.py --dry-run

四、给这一题评分
使用之前安装好的评测虚拟环境；PowerShell 命令：

& "D:\develop\huiAnswer\eval-venv\Scripts\python.exe" D:\code01\HuiAnswer\evaluation\score_generation.py --limit 1

默认只寻找 generation 目录中最新的采集文件，不会选到独立检索结果。
指定文件时使用 --results "<完整的results.jsonl路径>"。
模型配置沿用已有 HUIANSWER_EVAL_MODEL/HUIANSWER_CHAT_MODEL、
HUIANSWER_EVAL_BASE_URL/HUIANSWER_AI_URL。
API key 使用 HUIANSWER_EVAL_API_KEY 或 HUIANSWER_AI_API_KEY；
没有设置则隐藏输入。这里要填模型 API key，不是登录 token。

评分输出在：
<本次采集目录>/scores/<评分时间>/
- scores.jsonl：每题分数，以及评委拆分、支持关系等判定记录。
- summary.json / summary.txt：分项均分、有效题数、失败题数、不适用题数及主要/辅助角色。
- report.md：易读报告，逐题列出实际回答、修订参考答案、要点覆盖理由及缺少依据的陈述。
- scoring_run.json：评委模型、Ragas版本、评分口径、参考答案版本及SHA-256。
- judge-cache/：评委响应缓存。
原始采集文件不会被修改，所有 runs 产物都已被现有 .gitignore 忽略。

五、跑完整开发集
确认单题数据和评分正常后：

python D:\code01\HuiAnswer\evaluation\collect_generation.py
& "D:\develop\huiAnswer\eval-venv\Scripts\python.exe" D:\code01\HuiAnswer\evaluation\score_generation.py

全量是20道开发题，另有2次多轮题前置问答，总计22次业务问答调用。
多轮题只回放题集中历史的 user 输入，assistant 由真实接口回答；
不会将题集里的 assistant 样例强行写进业务库。
warmup_history 记录真实产生的历史，因此不宣称复现了逐字固定的历史样例。
每道题从新会话开始，不同题不会共享会话。
任何一次采集失败就停止，保留已完成结果；错误记录不会按0分处理。
需要重跑时再次运行脚本，会创建新目录，不覆盖旧结果。
评分模型的请求数不等于题数，一个指标可能多次调用评委模型。

六、评分口径 generation-v2
1. faithfulness（主要指标，Ragas内置）：
   检查实际回答的事实能否由本次实际上下文支持。
   单轮题使用 evaluation 返回的片段；
   多轮题还提供真实 warmup_history，单独记录为 faithfulness_contexts。
   预设参考答案和历史中的 assistant 样例不会加入证据。
2. answer_point_coverage（主要指标，自定义补充统计）：
   评委逐条核对必要回答要点，覆盖记1，否则记0；
   分数为 covered_points / total_points。
   数值、单位、条件和否定方向需正确，同义表达及正常主体省略可以认可。
   正确扩写不扣覆盖率；扩写是否有资料依据仍由忠实度检查。
   保存每个要点的编号、原文、判断和中文理由，缺失/重复编号视为评分失败。
   该指标不是Ragas的context_recall，不使用Ragas recall模式冒充要点覆盖率。
3. factual_correctness（辅助指标，Ragas内置）：
   使用修订参考答案计算F1，atomicity、coverage仍为high。
   仍可能因参考答案没有涵盖有效补充而扣分，因此只作辅助诊断。
   不额外调用embedding模型，不计算answer_relevancy/answer_correctness。
4. 无证据或评委没有提取到事实时，忠实度可为skipped，不强行当成0；
   其他指标独立处理，评分失败保留错误和空分数。
5. 4道特殊题仍标为manual_review，不纳入知识问答均分；
   对照expected_answer_points和forbidden_claims人工检查。后者仍不自动扣分。
6. 各项分开呈现，不合成为总分。参考口径修订后的分数不能当成问答系统优化收益。

七、边界
- 这些是开发集结果，独立测试集暂不使用。
- 评分脚本只读已采集结果，重复评分不会再请求 Java 问答接口。
- 本次不修改意图策略和响应延迟；http_elapsed_ms 只是采集请求的总时长。
- 评测结束可关闭 rag.evaluation.enabled 并重启，日常问答不再发送评测正文。

八、复用已经采集的问答，校准后重新评分
1. 无需重新运行collect_generation.py或重新调用Java问答。
2. 原dev.jsonl、all.jsonl、holdout.jsonl和业务文档保持原版本，
   新增参考文件只用于生成评测，避免改变原检索对照口径。
3. 评分结果中的reference、expected_answer_points来自修订版；
   collected_reference、collected_expected_answer_points保留原采集快照。
   reference_revision和reference_profile_sha256记录具体修订版。
4. 可用--references指定其他修订版；题号、问题必须与采集记录一致，不匹配时停止。
5. 先选003、008核对，再跑完整采集文件（PowerShell）：

& "D:\develop\huiAnswer\eval-venv\Scripts\python.exe" D:\code01\HuiAnswer\evaluation\score_generation.py --case-ids XL-003 XL-008 --dry-run
& "D:\develop\huiAnswer\eval-venv\Scripts\python.exe" D:\code01\HuiAnswer\evaluation\score_generation.py --case-ids XL-003 XL-008

确认两题的新报告判定合理后，去掉--case-ids处理全部已采集记录。
--case-ids先筛选，再由--limit限制数量。每次评分另建目录，旧结果保留。
默认取最新生成采集；需要固定某一次时，增加--results "<原采集文件完整路径>"。
