# 星澜商城四类意图检查 v1

16题，每类4题。复用原C组MT-001、MT-005、MT-008、MT-009的前置对话，不新增会话，不生成回答，不运行RAGAS。

## 如何运行

先重启本地后端，使评测接口读取新增的 historyBeforeQuestion 参数。它仅控制评测时的历史截断，不修改正常问答链路。

~~~powershell
$evalArgs = @(
  "D:\code01\HuiAnswer\evaluation\collect_intent.py"
  "--results"
  "D:\code01\HuiAnswer\evaluation\xinglan-multiturn-v1\runs\ablation-C\20261017-215153-278537\results.jsonl"
  "--cases"
  "D:\code01\HuiAnswer\evaluation\xinglan-intent-v1\cases\dev.jsonl"
)
& "D:\develop\huiAnswer\eval-venv\Scripts\python.exe" @evalArgs
~~~

使用创建原会话的同一个登录账号。脚本提示粘贴token；默认username是admin，可用 --username 指定。不保存token，不自动重试。

- 加 --dry-run：只核对题目和来源，不访问服务。
- 加 --limit 4：先测第一组的四种意图。
- 加 --case-ids INT-009 INT-011：仅复测指定的新题号。
- --results 是原来C组的问答采集文件，不是后来意图复测的 results.jsonl。

每题先改写，再对各子问题执行意图识别；通常需要两次模型调用，异常时可能触发备用。这里不会调用回答模型。

## 结果与分类边界

输出目录：evaluation/xinglan-intent-v1/runs/intent/时间戳/。

- report.md：按类别统计、逐题预期理由、原前置对话、完整改写、子问题及实际意图。
- results.jsonl：原始响应与结构化记录。
- summary.json：整体及每种预期类别的有效响应正确率、失败数。
- run.json：题集及来源哈希、运行状态，不保存凭证。

预期标签只供脚本比较，不发送给模型。
一个输入拆成多个子问题时，本套题要求所有子问题均符合它的单一预期意图，才算整题正确。
请求失败单列，不能因为失败被排除就只看有效响应正确率；同时看正确数/总题数。
本套题没有混合意图题，不能据此判断多意图组合是否处理正确。

CHAT是无需查资料的感谢、反馈等。CLARIFY是对象或范围没说清，需先补充。
NO_MATCH是问题清楚、但目录不覆盖；不等于不知道如何分类，也不等于资料不足就直接澄清。
当前业务里NO_MATCH还会全库检索；这个脚本只测路由，不检验它之后是否找到了片段。

## 历史复用方式

同一来源会话分别配四种新输入。脚本从原采集记录找出会话ID，发送新输入，并把原目标问题作为 historyBeforeQuestion。
后端只读取原目标问题之前的历史，不会把原目标问题或已生成的答案喂给改写模型。
找不到指定原题就报错，不会悄悄带上整个会话。
原采集的 warmup_history 只是报告里的核对材料，真正传给改写的历史仍由后端读取。
如果会话被删除，或后续长对话已使摘要/历史窗口覆盖原位置，需要重新建立来源会话。
